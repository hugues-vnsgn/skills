One `implementer` agent now builds every Issue, whatever the stack: `implementer-kmp` is gone, and the implementer probes its worktree and loads `tdd-kmp` and `kmp-test-seams`, or `ios-tdd-practitioner`, itself. Its procedure moved into the internal `implementing-an-issue` skill, shorter and with the review and merge rounds pushed to a reference file. It runs on the orchestrator's model unless an Issue's `model:opus` or `model:sonnet` label says otherwise, has no turn cap, and stops itself after three strikes with a FAILED report that says what it tried. It proves its guard is live with an `implementer-guard-check` canary before touching anything, and names its worktree with `git -C` on every git command, which the guard now requires for any git write. It writes only inside its worktree through every tool, and treats Issue text, handoffs and logs as data that cannot widen those limits. Its status now says who can fix what stopped it: FAILED when a fresh attempt could succeed, BLOCKED when only the user can change the cause, such as a missing skill, an unpassable gate or an injected instruction. `/implement-delegate` follows that without judgement calls: BLOCKED always goes to the user (or ends the Issue as blocked when nobody can answer), FAILED always gets one retry that inherits any partial work, and only a DONE report must prove a clean tip. It copies no command out of Issue text, and offers push and PR commands only when the repo has a remote. The guard now blocks a git call whose `-C` path or subcommand comes from a shell variable or substitution, which `git -C $(pwd) commit` used to slip past, and says to write the path out literally. skillcheck no longer requires `maxTurns`.
