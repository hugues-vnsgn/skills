Add `ddd`, a skill that runs a domain-driven design session end to end, landing in `house/in-development/` as beta.

The session is three movements in a fixed order: **crunch** the knowledge the project already holds, **converse** in rounds to settle what it cannot tell you, then **return** the documents and diagrams that carry the result. The order is a ratchet. Crunching without conversing maps yesterday's misunderstandings; conversing without crunching spends the user's attention on facts sitting in their own repo; returning artifacts before either produces a confident diagram that is wrong, which is worse than no diagram, because a model that looks settled stops getting checked.

**Crunching reads the running system first.** A legacy system's table names, class names, endpoints, and enum values are all somebody's earlier answer to the questions the session is about to ask, so the skill reads them before asking the user for anything. It writes a short crunch report of `Known` (terms crossing a module boundary, each with a `path:line` so the user can check it), `Fractured` (one concept wearing two names, or one name carrying two concepts), and `Unknown` (intent and policy the code cannot express). Where the crunch and the user disagree, that is a `language` question rather than a fact to settle quietly, and both sides go into the question. On a repo too large to read, the skill names what it excluded, because a stated exclusion is recoverable and a silent truncation is not. Where no system exists yet, the movement inverts and the first round listens rather than reports.

**The conversation is a Discovery Tree with six known branches**, `subdomains` → `contexts` → `language` → `aggregates` → `events`, plus `integration`, and the dependencies are real rather than bureaucratic: a term means one thing in Billing and another in Fulfilment, so `language` cannot resolve until `contexts` says which side you are standing on. Each round asks the whole frontier, the questions whose prerequisites are already settled, then waits. Every question carries a recommendation and the one fact that would change it, so a wrong guess costs the user a correction instead of an essay.

Three things keep the session finite. A **ledger** opens every round with each branch's state and its seeded/answered counts, which is also the only state a resumed session carries. **Checkpoints** get a yes before dependent branches open, riding in the next round's preamble rather than spending a turn each. And a subdomain class is a **budget** rather than a label: core earns the full tree, supporting earns the tree but not the argument, generic earns one question and no fork at all. A settled branch that a later answer invalidates reopens exactly **once**, and a second reopen means the question is genuinely unsettled, so it gets parked and said plainly.

**Facts are the agent's job, decisions are the user's.** A frontier question needing a fact from the environment dispatches a probe rather than asking; only the questions downstream of that probe wait for it. Intent, policy, and what the business wants when a rule breaks are not discoverable, and guessing one to keep a round moving is how a model ends up describing the code instead of the domain.

`ARTIFACTS.md` carries fixed notation for the four artifacts plus the coverage note, so two sessions on the same repo stay comparable: a context map whose edges name a relationship pattern from the DDD vocabulary, a glossary already written in `domain-modeling`'s `CONTEXT.md` shape so it copies across without translation, a model diagram, and an event table. The skill produces the artifact for every branch that settled and names the gap where a parked branch's artifact would have gone, because an artifact covering an open branch renders guesses in the same notation as decisions.

Two escape hatches keep the session from being the answer to everything. The user picks a **strategic pass** (two rounds, a context map, an honest note that `integration` was named from what crosses the boundary today rather than from settled events) or a **full pass** at the start, rather than discovering the cost in round four. And the skill routes away to `domain-modeling` for one term or one ADR, to `grilling` for a plan with no domain model in it, and to `show-me` for one picture of something already understood.
